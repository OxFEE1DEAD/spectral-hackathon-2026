ПОЧЕМУ 2xlarge МИНИМУМ ДЛЯ ДЕВА
  8 vCPU = 4 физических ядра. Нужно изолировать: producer, sender, +2 под
  housekeeping/IRQ. На xlarge (2 физядра) изолировать нечего.
  вместо xlarge за $0.20/ч: экономит $26 и ломает саму методику. Нет.

ПОЧЕМУ 8xlarge ТОЛЬКО НА ФИНАЛ
  8xlarge даёт sustained 12.5 Gbps. У 2xlarge и ниже — "up to 12.5", т.е.
  burst-кредиты. Их исчерпание = обрыв латентности в середине прогона,
  который выглядит как наш баг. На матрице до насыщения это неприемлемо,
  на дев-итерациях (низкий rate) — безразлично.

ШАГИ
  1. bench/aws-up.sh:
       aws ec2 create-placement-group --strategy cluster
       ВАЖНО: placement group задаётся ТОЛЬКО при launch. Судья не сможет
       добавить задним числом -> точные команды идут в docs/REPRODUCE.md.
       run-instances: m7i.2xlarge x2, один AZ, одна подсеть, Ubuntu 24.04,
       SG разрешает UDP+TCP внутри группы.
  2. bench/aws-down.sh: stop (не terminate) — сохраняем EBS-состояние
     между сессиями (~$0.08/ГБ-мес против пересборки окружения каждый раз).
  3. На инстансах: cron с `shutdown -h +90`, обновляемый heartbeat'ом
     во время активной сессии. Забыл погасить — гаснет само.
  4. bench/deploy.sh: rsync исходников + make на удалённой машине.

ПРОВЕРИТЬ В ПЕРВЫЙ ЧАС (иначе 18 дней оптимизируем шум)
  ethtool -T eth0                  что реально доступно из таймстемпов
  ethtool -i eth0                  версия ENA-драйвера (нужен >=2.10 для PHC,
                                   >=2.15 для HW RX ts, >=2.16 для AF_XDP ZC)
  grep -o 'constant_tsc\|nonstop_tsc\|tsc_reliable' /proc/cpuinfo | sort -u
  cat /sys/devices/system/clocksource/clocksource0/current_clocksource
      ^^^ если тут kvm-clock, а не tsc — util::now_ns() в САМОМ harness'е
          становится в ~10 раз дороже и джиттернее. Меряем не то. Чинить
          немедленно через clocksource=tsc в cmdline.
  ls /dev/ptp0                     есть ли PHC вообще
  lscpu -e                         карта физядер vs гипертредов (не пинить
                                   producer и sender на сиблинги одного ядра)

ЗАПРОС К ЖЮРИ (идёт в райтап; README прямо приглашает)
  "Зафиксируйте m7i.8xlarge, один AZ, cluster placement group, Ubuntu 24.04,
   ENA >=2.16 с phc_enable=1, chrony на /dev/ptp0. Решение работает на любом
   типе и на m8a; числа сняты на этих настройках."
  Плюс просим 3 хоста-получателя. Отдельно поддерживаем N получателей на
  одном хосте (разные порты + разные имена SHM) — это разные бутылочные
  горлышки (общий NIC против общей фабрики), меряем обе топологии.
