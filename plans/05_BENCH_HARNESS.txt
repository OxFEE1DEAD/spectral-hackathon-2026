05  BENCH HARNESS — инжекторы потерь и автоматизация прогонов
    день 5 (8 ч)

решения: D-14 (свой дроппер + netem)

ЦЕЛЬ  один прогон = одна команда = один воспроизводимый бандл.
      Без этого прогресс не виден и итерации не сравниваются.

ИНЖЕКТОРЫ ПОТЕРЬ — ДВА НЕЗАВИСИМЫХ, ОБА В РЕЗУЛЬТАТАХ [D-14]
  1. Детерминированный дроппер внутри receiver'а: hash(dgram_id) < threshold.
     Точно воспроизводим, кернел-независим, судья повторит БЕЗ root.
     Это ПЕРВИЧНЫЙ инструмент для науки.
  2. tc netem loss random 1% / loss gemodel.
     Реалистичнее, но зависит от версии ядра, недетерминирован, сидит в TX-пути
     и добавляет свой джиттер. ВТОРИЧНЫЙ, для проверки реализмом.
  Gilbert-Elliott обязателен: реальные потери идут пачками, и именно пачки
  ломают одиночный parity и стаггер Δ=0.

СКРИПТЫ
  bench/env_check.sh   ОТКАЗЫВАЕТСЯ стартовать на нетюненном окружении.
                       Проверяет: isolcpus, governor, C-states, IRQ affinity,
                       clocksource, chrony synced, ENA-счётчики обнулены.
                       почему отказ, а не предупреждение: иначе однажды
                       сравним яблоки с апельсинами и не заметим.
  bench/run.sh         один эксперимент: параметры -> results/NNN-имя/
  bench/matrix.sh      прогон по осям
  bench/collect.sh     сбор окружения в бандл
  bench/loss_inject.sh обёртка над обоими инжекторами
  bench/regress.sh     одиночный хост, сравнение с сохранённым бейслайном,
                       падает при регрессии p50/p99/p99.9 сверх порога.
                       Гоняется на каждом коммите БЕЗ AWS.
  bench/run_all.sh     работает без root и без тюнинга (см. файл 15)
  bench/tune.sh        требует root

ФОРМАТ БАНДЛА  results/NNN-имя/
  params.json      параметры прогона
  meta.json        git sha, ядро, тип инстанса, версия ENA, AMI id, карта ядер
  lat_recv_N.csv   seq,latency_ns на каждого получателя
  stages.csv       гистограммы по стадиям (появится в файле 06)
  counters.json    NIC drops, UDP errors, ретрансмиты, восстановления, лапы
  clocks.json      chronyc tracking до/после, phc_error_bound, clockbound
  report.md        авто-сводка

ДИСЦИПЛИНА ПРОГОНА
  прогрев -> отбросить первые N -> фиксированная длительность 10-30 с
  (>30 с рискуем дрейфом часов, см. 02).
  >=10 M сообщений на точку: на p99.99 должно приходиться >=1000 сэмплов,
  иначе цифра нестабильна и её нельзя сравнивать между итерациями.

ТАБЛИЦА ПРОГРЕССА
  Каждая фаза дописывает строку: итерация x {p50,p99,p99.9,p99.99,
  max rate при p99.9<цели, drop rate}. Это и есть "виден ли прогресс".
